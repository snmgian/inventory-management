# Application Audit: Security, Performance, UX

**Date:** 2026-11-12
**Scope:** Full repository at commit `f26617b` (client, server, CI workflows, repo tooling)
**Method:** Three independent reviewers (Security, Performance, UX) audited in parallel, exchanged cross-domain leads, then challenged each other's severity ratings. Disputes were settled by the team lead after checking the disputed claims against the code.

## Summary

- 44 raw findings, about 35 after merging duplicates across domains.
- **5 High**, all user-facing: keyboard lockouts (UX-2, UX-3), lost user input (UX-4), wrong currency amounts in Japanese (UX-5), and charts showing wrong values (UX-7).
- **No security or performance finding is High for the demo as it runs today.** Three become High in a production deployment: the unauthenticated write API (SEC-1), the open CORS policy (SEC-2), and the unbounded order request (SEC-4 / PERF-1).
- No injection vectors (no `v-html`, no templates, no database), no committed secrets or private registry URLs, no memory leaks, and every backend endpoint responds in about 1 ms at today's data size.

### How the review was done

- Static code review. The frontend and API servers were not running, so responsive layout and accessibility were judged from code and CSS, not tested in a browser.
- The backend was exercised in-process with FastAPI's `TestClient` (no server started) to confirm runtime behaviour, measure response sizes and time requests.
- The client was built separately to measure bundle sizes, including a variant with lazy-loaded routes.
- "At scale" means 100x today's data: 25,000 orders instead of 250.
- No repository files were changed during the review.

### Severity scale

| Severity | Meaning |
|---|---|
| High | Users are blocked from a feature, lose data, or see wrong figures presented as fact; or a security issue exploitable today with real impact |
| Medium | Real defect with limited reach or a workaround; or a security/performance issue that becomes High in production or at scale |
| Low | Polish, hardening, hygiene, or problems that only appear at much larger scale |

Where a rating differs between this demo and a production deployment, both are given.

## Rating disputes and decisions

| Finding | Ratings proposed | Decision and reason |
|---|---|---|
| SEC-4 / PERF-1 oversized order request | Performance: High. Security and UX: Medium | **Medium in the demo, High in production.** Performance conceded. The only effect today is the demo server going down, a restart recovers it, and crashing a 16–32 GB laptop takes 15–30 concurrent requests. Fixed first anyway because the fix is one line. |
| UX-7 wrong chart values | Performance: High. UX: Medium, "closest to High" | **High.** The Spending cost chart has a hard-coded $25K maximum while real monthly values are $145K–$1.87M, so every bar is clipped flat and the chart carries no information. Same reasoning as UX-5: wrong financial data on a default view. |

## Prioritized action plan

### Phase 1: Quick wins (all small; about 1–2 days)

1. **Harden `POST /api/restock-orders`** (SEC-4/PERF-1, SEC-3, SEC-5, SEC-6, SEC-13)
   - Cap `items` with `Field(min_length=1, max_length=9)` (or derive from the number of forecast SKUs) and add a request body size limit.
   - Use strict types and `extra="forbid"` on both request models.
   - Register a custom `RequestValidationError` handler that does not echo the input. This fixes the NaN/Infinity 500 and the reflected input in one change.
   - Generate order IDs from a lock-protected counter (or UUIDs) instead of `len(restock_orders) + 1`.
   - Add POST tests for NaN, Infinity, `1e400` and oversized bodies.
2. **Close off the network** (SEC-2, part of SEC-1)
   - Replace `allow_origins=["*"]` with an allowlist from an env var (default `http://localhost:3000`), set `allow_credentials=False`, and limit methods to `GET, POST`.
   - Bind to `127.0.0.1` by default; allow `0.0.0.0` only through an env var.
3. **Fix wrong numbers** (UX-7)
   - Compute the Spending cost chart maximum from the data.
   - Use `2 * Math.PI * r` for the Dashboard donut circumference.
   - Remove the duplicate plus sign ("++12.3%"), pass inventory fields so ProductDetailModal doesn't show "undefined units", and guard the division that produces "Infinity%".
4. **Make the header menus keyboard-operable** (UX-2)
   - Use `@click` instead of `@mousedown.prevent` on menu items; close on `focusout` only when focus leaves the menu, and on Escape; add `aria-expanded` and `aria-haspopup`.
5. **Deal with the dead features** (UX-4, UX-6)
   - Hide the Create PO / View PO column until the feature exists.
   - Either add `/api/tasks` (with the same limits as item 1: max lengths, strict model, capped list) or remove the Tasks feature. Either way, clear the task form only after a successful save and show an inline error on failure.
   - If a purchase-order endpoint is built later, re-price on the server as `restocking.py` does: the existing `CreatePurchaseOrderRequest` takes `unit_cost` from the client.
6. **Repo hygiene** (SEC-12, SEC-9)
   - Add `.claude/settings.local.json` (and `.claude/*.local.*`) to the repo `.gitignore`.
   - Remove the Claude session links from `docs/superpowers/plans/2026-11-12-restocking.md` and keep them out of future committed docs.

### Phase 2: Correctness and accessibility (about one sprint)

7. **Japanese currency** (UX-5): route every monetary value through `formatCurrency` / `formatCurrencyWithDecimals` and delete the `currencySymbol` computeds (about 25 sites across Inventory, Orders, Spending, Reports and the detail modals).
8. **Keyboard-accessible triggers and a shared modal** (UX-3 with UX-1): put real `<button>` elements in clickable rows and chart bars, and build one `BaseModal` with `role="dialog"`, `aria-modal`, `aria-labelledby`, Escape to close, focus trap and focus return, and a labelled close button.
9. **Shared fetch composable for all data views** (UX-9/PERF-4, PERF-7/UX-19a): copy the `requestSeq` pattern from `Restocking.vue`, reset the error at the start of each load, add Retry, and show the full-page loading state only on first load.
10. **Server-side aggregates that respect filters** (PERF-2, UX-16): serve Dashboard and Spending totals from the API instead of shipping the full orders list; hide or disable filters on pages that ignore them.
11. **Restock flow polish** (UX-10): `aria-live` for success and errors, a confirmation step showing the total, a retry state when the first load fails, `aria-valuetext` on the budget slider, and translated error messages instead of raw axios or server text.
12. **Shared date utility** (UX-11): parse `YYYY-MM-DD` as a local date, return a placeholder for invalid dates, and compare months by string prefix.
13. **Small accessibility fixes** (UX-13, UX-14, UX-15): update `document.documentElement.lang` in `setLocale`; associate filter labels with their selects and label the search input, checkbox and icon buttons; switch failing text colours to `#64748b`, `#b45309`, `#047857`, `#2563eb` and `#dc2626`.

### Phase 3: Translation, responsive layout, cleanup

14. Move hard-coded English strings into the locale files, format dates and numbers with `Intl` using the current locale, and add the missing product and customer name translations (UX-12).
15. Add breakpoints at 1024px and 640px: collapsible nav, wrapping filter bar, single-column grids, `minmax(min(450px, 100%), 1fr)` (UX-8).
16. Clean up the Reports page (PERF-8, SEC-11): route calls through `api.js`, read the API base URL from `import.meta.env.VITE_API_BASE_URL` with a Vite dev proxy for `/api`, use `Promise.all`, remove the `console.log` calls, compute the chart maximum once.

### Phase 4: Before production or larger data

17. Add authentication and role checks on write endpoints; disable `/docs`, `/redoc` and `/openapi.json` outside development (rest of SEC-1).
18. Scale work: paginate `/api/orders` (PERF-3), add `GZipMiddleware` (PERF-6), lazy-load routes (PERF-11), cache `Intl` formatters (PERF-10), index Top Products by SKU (PERF-9), trim redundant requests (PERF-5), precompute reports and ID lookups at startup (PERF-12).
19. Supply chain: pin GitHub Actions to commit SHAs and pin the plugin marketplace ref (SEC-7); pin MCP server versions and move to the maintained GitHub MCP server with a least-privilege token (SEC-8); redact secrets in the logging hook if it is ever enabled (SEC-10).
20. Remaining UX polish: status conveyed only by colour and charts without text alternatives (UX-17), empty states (UX-18), and the rest of UX-19.

## Checked and found fine

- **Injection:** no `v-html`, `innerHTML`, `eval` or `document.write` in the client. The server has no database or templates and reads only fixed filenames. The POST path re-prices every line from server data.
- **Secrets:** no credentials, private registries or internal hostnames in tracked files or history; `client/.npmrc` pins the public registry; `.env` is gitignored; workflows use only `secrets.ANTHROPIC_API_KEY`.
- **Workflows:** `pull_request`, not `pull_request_target`; no untrusted input interpolated into `run:` steps; read-only permissions.
- **Backend performance:** Pydantic validation of 250 orders takes 0.5 ms; sync endpoints run on the threadpool and do not block the event loop.
- **Frontend:** no leaked listeners or intervals; modals mount only when open; no deep watchers; most views already use `Promise.all`. `Restocking.vue` is the model to copy: debounced input, stale-response guard, timer cleanup on unmount, double-submit guard.
