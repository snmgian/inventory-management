Architecture overview

Factory Inventory Management System

A full-stack demo: a Vue 3 single-page app talks to a FastAPI service over JSON. The service holds all data in memory, loaded from JSON files at startup. There is no database, and nothing persists between restarts.

System architecture

Three tiers, each running locally. The browser calls the API directly at localhost:8001. There is no Vite proxy, so the backend uses CORS to allow requests from any origin.

Data flow: changing a filter

What happens when someone picks a warehouse, category, status, or time period in the global FilterBar.

User changes a filter client

FilterBar.vue writes to refs in useFilters. The refs are module-level singletons, so every view shares the same filter state.

Active view reacts client

Each view watch()es only the filters it supports. Inventory and Demand watch location and category, Spending watches period, and Dashboard and Orders watch all four. The view then calls getCurrentFilters().

Request is built client

api.js maps period to month, drops any value set to "all", and sends GET requests such as /api/orders?warehouse=…&month=Q2-2025. Dashboard sends four requests in parallel with Promise.all.

Filtering in memory server

The handler runs apply_filters() (exact warehouse match, case-insensitive category and status), then filter_by_month() (substring match on order_date, with quarters expanded through QUARTER_MAP). The global lists are never changed.

Validation and serialization server

The response_model Pydantic classes validate the output and serialize it to JSON. Summary, spending, and report endpoints return plain dicts without a model.

Reactive render client

Raw responses are stored in refs such as allOrders and inventoryItems. Computed properties derive KPIs, chart series, and table rows from them. formatCurrency converts to JPY at a fixed rate of 150 when the locale is ja.

Gaps found during review

Mismatches in the current code. Nothing here has been changed.

Task endpoints are missing on the backendApp.vue calls api.getTasks() and api.createTask(), but main.py has no /api/tasks routes, so these requests return 404. Purchase-order routes in api.js are also missing on the backend.
Backlog view is not routedviews/Backlog.vue exists but is not registered in main.js or linked in the nav. Backlog data appears only on the Dashboard.
API base URL is hard-codedapi.js and Reports.vue both hard-code http://localhost:8001. Reports bypasses the shared API client entirely.
Quarter logic is duplicatedQUARTER_MAP and the if/elif chain in /api/reports/quarterly define the 2025 quarters separately, and both only cover 2025.
Some responses have no schemaThe dashboard, spending, and reports endpoints return plain dicts with no response_model, so their response shapes aren't validated or documented in /docs.
